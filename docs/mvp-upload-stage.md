# M3：无凭据上传适配与离线验收

本轮交付可运行的直接 API 分片流程、注入式传输边界、内存模拟器、SpaceGuard 生命周期接线、源/回读双哈希闸门及机器可读结果。此文保留前轮纯模拟阶段的范围；后续已补齐 [HTTP 协议绑定与审查](mvp-baidu-http.md)，但没有凭据加载入口，模拟入口仍拒绝 live，严格冲突策略缺口使实网写入继续关闭。模拟通过不代表真实网盘上传、回读、账号权限或全过程空间保护通过；M2/M3 真实联调尚未验收。

## 选择与资源上界

采用直接 API 流程而非本轮再引入 OpenList 进程，依据是已有独立基线已验证分片上传/回读，而直接流程不需要另存完整上传副本。逐片回执及空间检查可直接接线，维护面较小。保留历史 OpenList/直接 API 证据，不重新测速或做续传实验；这不是长期性能优劣结论，也不是对旧实验脚本的生产化导入。

- `upload_stage.py`：源收据及文件重验、隔离目标、分片回执、远端长度、完整流式回读、停止确认与状态记录。
- `simulated_cloud.py`：纯内存假远端。不存在网络、环境变量或凭据配置；独立于旧 PoC 和未提交实验。
- `m3.py`：必须显式 `--simulate`；没有自动或隐含的 live 路径。
- 每个模拟文件最多 16 MiB；CLI 每片 4 MiB、流式回读块最多 1 MiB。通用流程限制每片不超过 32 MiB、回读块不超过 1 MiB、最多 1024 片，同时要求显式单文件上限。**这些是本地模拟限制，不是已核实的百度账号上限**。
- 不复制整文件到磁盘缓存；模拟器在内存中保留载荷，提交时可能同时存在分片与合并对象，所以 RAM 不是零开销。小文件上限防止把它当作大规模真实网盘替身。
- CLI 的 64 KiB 源元数据额度、上传/回读各 256 KiB 后端额度，只适用于此实现的有界收据和两个最多 16 KiB 的状态文件；仍按文件系统块取整检查。不是实际百度/OpenList 后端开销的默认值。低额度或未知额度会停止，不强行执行。

## 验证闸门与状态

输入仍须先通过 M1。读取 M2 收据要求 `status=source_verified`、文件名、正整数长度、本地 MD5/SHA-256 与实际文件一致；同时独立核对 manifest 的源站摘要。文件通过无符号链接的普通文件描述符读取，并核对 inode/长度/mtime/ctime；先计算全文件与分片哈希，再在发送各片前复核，变化则停止。收据最多读取 16 KiB；不读取任何授权配置。

目标由受限 app_name、job_id 和已校验文件名构造为 `/apps/<app>/mvp-validation/<job_id>/<name>`，不接受任意远端路径。单任务占有新的 0700 本地目录；存在的任务目录立即拒绝，不读取/覆盖其状态，不重新上传。模拟远端采用 reserve_new / begin_new / commit_new 的禁止覆盖契约，重名拒绝。真实 API 必须另行证明能兑现该契约，不能把模拟原子性当成百度接口保证。

每片回执 MD5 必须匹配，提交后远端长度必须是准确整数，再完整流式回读并计算长度、MD5 和 SHA-256。只在这些检查全部通过、任务适配器停止已确认、最终状态记录写入成功后，返回 `verified_simulation` 和 `simulated_delivery_eligible=true`。

所有结果始终是 `mode=simulation`、`cloud_verified=false`、`delivery_eligible=false`，因此**不能交给真实分享/交付流程作为放行凭据**。失败统一为 manual_review 加安全原因码。异常原文、原始响应、传输 session、令牌及签名 URL 不进入记录。停止不确认、状态写入失败也撤销模拟资格。

任务自有状态用 0600 的 state.new 独占创建、fsync 后替换本次已拥有的 state.json；不覆盖任务外数据。源校验/预算未通过时可能只有新占有的空任务目录，失败结果仍通过返回值/CLI 输出，不为记录错误而突破磁盘预算。后续阶段空间不足时保留原进度，返回 state_persisted=false，不将无法持久化的结果视为成功。没有保存真实 uploadid，也没有实现分片恢复或 M5 全任务持久化；同一 job_id 重启仅会拒绝，人工处理后用新任务继续。

## M2 接线与停止边界

复用已有 SpaceGuard，不重写预算算法。preflight_workspace 只增加可注入 probe 参数，保留原默认行为，供同盘/分盘测试复用。

1. 创建新任务目录之前检查精确存在的源/后端目录及系统保留线；未知需求先拒绝。
2. 源校验过程使用 download 检查；源长度及哈希通过后进入 upload。
3. 状态文件按 backend_extra 登记；任务适配器可通过 AdapterContext 登记隔离目录内的非凭据临时文件，在写入前报告分配上界，并在检查点核验实际占用。
4. attach、保留新目标、发送各片、提交、读取元数据及回读阶段前后检查；回读流每块检查。临时文件在阶段间保留，必须计入下一阶段额度，不自动删除以制造空间。
5. 错误或空间下降停止继续提交/读取，并请求本任务 transport.stop()；不操作系统中其他进程，不删除云端对象。不确认停止就返回人工处理。

这是同步、协作式接口；模拟器无独立后台写入。真实 transport 仍需绑定超时、确认账号及单文件/分片限制、准确登记真实临时文件、证明缓冲/停止延迟在余量内并实测全过程至少 5 GiB。不得由模拟 stop=True 推导实际进程已受控，也不提供内核配额或多用户调度。

## 可复现离线执行

先准备一个已由 M2 下载且保有 `.receipts/<index>.json` 的源工作目录，以及一个精确存在的私有模拟后端父目录，再执行：

```sh
python3 -m fast_transfer.m3 --simulate examples/ncbi-ecoli/manifest.json \
  --source-dir /path/to/verified-source --backend-dir /path/to/private-simulation \
  --job-id unique-simulation-job
```

这里只访问本地文件和内存假远端；不从源站重新下载，也不访问百度。不要对历史任务复用 job_id。退出码 0 仅表示模拟成功，2 表示人工处理。程序输出 JSON，任务目录保留脱敏状态文件。

本轮复用了已保留的真实 NCBI FASTA（1,379,902 字节）和 M2 收据，完成一次本地模拟，源与假远端回读的 MD5/SHA-256 一致；见 `docs/validation/mvp-m3-simulation-2026-11-08.json`。这里的“真实”仅描述源数据内容，远端是内存模拟器；没有新的真实网盘文件。

测试：

```sh
python3 -m unittest discover -s tests -p test_upload_stage.py -v
python3 -m unittest discover -s tests -v
python3 -m compileall -q fast_transfer tests
```
