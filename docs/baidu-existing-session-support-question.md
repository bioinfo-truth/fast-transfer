## 可复制的问题

我们按预上传→分片上传→创建文件的流程上传公开数据。已有预上传会话，部分分片成功并持久保存MD5回执；某一分片在HTTP响应返回前客户端中断，该分片的服务端结果未知。我们不希望重传已成功或结果未知的请求。

请确认：

1. 是否有官方支持的接口，能查询**指定已有uploadid**已接收/仍缺失的分片序号及对应MD5？请提供完整URL、HTTP方法、鉴权方式、参数和响应字段，以及会话过期时的错误。
2. 预上传文档列出了可选uploadid。再次POST precreate并传入原uploadid、原path/size/完整block_list时，是否严格沿用原会话？是否可能创建新会话、重置已有分片、变更目标或触发快速完成？返回的block_list对该**原会话当前状态**有何保证？空列表如何解释？
3. 如果没有查询接口，重复相同uploadid/partseq及完全相同内容的请求，服务端是否保证幂等？发生响应丢失、会话过期、节点切换时保证是否一致？请给出官方依据。此问题用于评估策略，不表示我们已允许重发未知请求。
4. 不重传该未知片的条件下，是否有其他官方支持的确认方法或可供支持人员查询的服务端记录？应私下提供哪些最少标识？

我们需要的是可验证的恢复契约；一般网络失败重试建议、SDK高层重试代码或最终文件不存在，均不能单独证明未知片没有被接收。
