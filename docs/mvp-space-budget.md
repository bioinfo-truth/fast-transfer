# M2：后端感知的空间预算与检查接口

本轮完成预算组件、下载接线和离线/模拟验证，不调用任何云端接口、不使用凭据。M2 的源下载与源站校验已有真实小样例证据；**实际上传/回读期间的全过程空间保护尚未验证，须在 M3 联调验收**。不能据预算模型测试将整个 M2 标为完成。

## 资源与开销必须分开声明

`fast_transfer/space.py` 的 BackendNeeds 接受操作人员提供的预算上界，不接受来自客户 manifest 的任意后端配置：

| 项目 | 来源及含义 |
| --- | --- |
| 源文件 | 所有本任务保留的源文件；逐文件按所在文件系统分配块取整。已经占用的部分抵扣，不再次申请整份空间。 |
| source_overhead_bytes | 源工作区的收据、任务自有元数据等额外磁盘开销总上界；所有阶段保留。source-only 的本地收据额度默认 1 MiB，不是后端开销估计。 |
| OpenList 整文件缓存 | 额外一份最大源文件，位于 backend_dir；只允许一次处理一个后端文件。为保守起见，在回读阶段继续保留此容量，不假定上传结束已自动清理。 |
| 直接 API | 模型要求不生成额外整文件上传副本；仍必须声明临时开销。若实际适配器会落盘副本，不得使用此 profile 掩盖它。 |
| upload_temp_bytes / readback_temp_bytes | 后端目录中除整文件载荷外，上传/回读阶段所有任务自有临时文件、日志等的总分配上界；包括上一阶段仍保留的临时文件。不能只填本阶段新增长量。 |
| readback_mode | stream 不保留整份回读副本；file 另计一份最大文件，位于 backend_dir。未明确则转人工处理。 |
| 固定保留线 | 每个相关文件系统至少 5 GiB；系统根文件系统也检查。 |
| 提前停止余量 | 每个文件系统另加 256 MiB，独立于上述所有开销，不能代替后端临时文件预算。 |

OpenList/direct-api 的三个开销参数与回读方式缺失时安全拒绝为 manual_review，不能假定为零。显式已知的零是可表达的模型输入，但不是该后端真实需求已经验收；必须由 M3 根据实际适配器证明。当前没有经本轮真实上传校准的通用后端默认值。未知后端、错误阶段或不适用参数同样停止。

## 同盘与分盘规则

DiskProbe 只接受精确存在的目录，不向上寻找最近父目录来猜测缓存位置；拒绝符号链接、缺失目录和非目录路径。用 st_dev 区分文件系统，不凭目录名判断“分盘”。同一文件系统的各资源相加后只加一次保留线/余量；分盘分别核验，不能拿另一块盘的空闲容量抵账。

`expected_layout='same'/'separate'` 可明确要求同盘或分盘，实际不符即停止，防止预期独立挂载已缺失却写入系统盘。auto 只反映当前实际布局，不能证明某个目录符合操作人员原本的挂载意图。初始化后记录目录 device/inode/块大小及文件父目录身份，每次检查发生变化就停止；已登记文件的设备变化、硬链接别名和符号链接也拒绝。不修改挂载、路由或系统配置。

创建全新输出工作区之前先对现有父目录、系统盘及所给后端目录做保留线检查，加 1 MiB 创建目录额度；只显式创建一个新的子工作区，不创建缺失挂载目录树。新目录建立后用其真实文件系统身份重新计算完整预算。

### 剩余容量，不重复计算已占用容量

模型读取任务显式登记的普通文件 stat/st_blocks，不读取其内容，不扫描或删除任意旧文件。源文件抵扣按每文件分配量与其目标大小上界取小；一个文件超额预分配不能替另一文件支付预算。缓存/回读载荷按实际分配量与当前逻辑大小的块取整值取小；稀疏文件未分配的块不抵扣。其他临时文件按实际分配量抵扣，并受当前阶段总上界约束。未登记旧文件只通过系统剩余空间反映，不能冒充任务缓存进行抵扣。

对每个文件系统 d，当前及未来各阶段 p 分别计算：

```text
remaining(d,p) = sum(max(target(resource,p) - credited_allocation(resource), 0))
required_free(d) = max(remaining(d,p) for current/future p) + 5 GiB + 256 MiB
```

必须先合并同盘的同时存在资源，再取阶段峰值；不能把源文件和缓存的峰值分别取最大后漏掉同时占用。所有大小/开销按各自文件系统的分配块向上取整。

单文件、尚未下载、同盘、流式回读时（略去块取整），设文件 F，源开销 S，上传额外开销 U，回读额外开销 V：

- OpenList：`2F + S + max(U,V) + 5 GiB + 256 MiB`。
- 直接 API：`F + S + max(U,V) + 5 GiB + 256 MiB`。
- 保留整份回读时，分别比较上传阶段与回读阶段额外 F，不能把流式回读当成整份副本免费。
- 多文件下载会保留全部源文件；源目标为所有文件之和，后端载荷为最大的一个文件。因此末尾小文件不能挤掉前面大文件的缓存预算。

分盘时，源盘计算源文件与 S；后端盘计算缓存/回读载荷及其阶段开销；系统盘即使不写文件也检查保留线/余量。重叠在同盘的角色只加一次底线。

## 接线与可执行接口

`SpaceGuard.check(stage, growth=...)` 可用于下载前、阶段切换和每次受控写入前。检查失败抛出带安全原因码的 SpaceProblem（manual_review）；空间不足报告给出角色、空闲字节和需求，不暴露实际路径或 URL。成功的阶段不允许倒退；进入 upload/readback 前要求源文件长度齐备，这只是空间前提，**不代替源站哈希/上传结果验收**。

- 下载器已接入检查：请求前、响应后/新文件创建前、读写循环、最终校验后和收据写入前后。每块写入后 flush，让下一次检查观察实际分配块，而不是只相信内存进度。
- 源/缓存/回读载荷的 growth 是本次新增逻辑字节，覆写预分配范围为 0；其他临时文件的 growth 是本次新增物理分配上界，要包含块取整。源下载器另按每文件预期长度拒绝超限。
- 适配器必须先用 register 登记其隔离工作目录中的缓存/临时文件；不允许将未知旧文件抵扣。目录必须精确存在，已登记文件可以尚未创建。
- 阶段开销若低于仍保留临时文件的实际总占用，切换会被拒绝；组件不会替调用者删除文件，须按已有授权和保留规则处理后再检查。

CLI 默认为 `--backend source-only`，仅对源阶段负责；默认收据额度 1 MiB，不声称能开始上传。可选 `--backend openlist` 或 `direct-api` 仅增加磁盘计划，不启动上传，必须显式给出 `--backend-dir`、`--source-overhead-bytes`、`--upload-temp-bytes`、`--readback-temp-bytes` 和 `--readback-mode stream|file`。`--expected-layout same|separate|auto` 控制布局预期。参数缺失/未知进入人工处理；没有跳过后端预算的强制执行选项。启动时输出 space_admission JSON，与 source_verified 结果分开。

## 离线验收与 M3 剩余项

执行：

```sh
python3 -m unittest discover -s tests -p test_space.py -v
python3 -m unittest discover -s tests -p test_safe_download.py -v
python3 -m unittest discover -s tests -v
```

预算测试覆盖同盘求和/分盘独立保留、系统盘不足、块取整、已下载源、缓存增长、稀疏/超额预分配、保留临时文件跨阶段、未知开销、错误路径/设备/别名、预期挂载布局、阶段倒退、批量源与最大缓存、动态空闲下降。1,000,000,000 / 5,000,000,000 字节只作为整数边界；不生成大文件。模拟上传适配器只改变内存分配账本，在继续写入前停止；无网络连接。CLI 离线测试用微小 BytesIO 模拟源站响应，核对源结果/收据、后端目录为空，以及预算不足/未知开销不请求数据。

M3 尚须：选择实际适配器并核实磁盘开销上界、登记真实缓存/临时文件、将阶段及写入检查接入其生命周期、控制独立后端进程安全停止、验证缓冲和停止延迟在余量内、测试真实上传与回读全过程至少保留 5 GiB。若后端无法配合检查，不能据此组件承诺全程保护。后端自己的请求、重试和后台写入均未因预算组件而自动受控。

本组件不是内核空间预留/配额，不防止其他进程在两次检查之间抢占空间，也没有后台监管线程、多用户调度或持久任务恢复。限单任务、顺序处理；文件系统自身配额/压缩等会影响分配计量，写入异常仍需安全停止。不能将模拟空间下降验证、旧工具大文件试验或先前源下载成功替代本轮真实上传期验收。

## 对照原 M2 完成标准

| 原验收项 | 本轮可确认的证据 | 剩余验收 |
| --- | --- | --- |
| 从 M1 公开链接逐文件下载、核对字节及源站摘要、计算本地 MD5/SHA-256 | 既有真实 NCBI 小样例记录保留；本轮变更用模拟源离线回归，不重新下载样例或生成大文件 | 未进行本轮新版本的海外 VPS 实传或大文件回归 |
| 源站无哈希时明确证据缺口 | M1 保持 manual_review 并禁止自动下载，有测试 | 不提供跳过源站校验的自动上传路径 |
| 源文件、上传后端额外缓存及临时开销预算 | 已实现后端需求声明、未知开销拒绝、实际文件系统分组、块取整及已占用抵扣；同盘/分盘及 1 GB/5 GB 整数模型通过 | 真实适配器的临时开销上界、缓存登记及全过程保护待 M3 |
| 全程保留至少 5 GiB，超限拒绝/暂停，不写满系统盘 | 源下载已接入检查，阶段/写入前接口和模拟适配器安全停止通过；每个文件系统加独立保留线和余量 | 没有真实上传/回读进程，未验证独立后台写入的缓冲、监测/终止延迟；不能宣称全程实测通过 |
| 错误 URL、下载中断、空间不足、哈希错误和危险重定向 | 契约、源下载及空间测试覆盖；失败清理仅限本次新建未验证文件，旧文件保留 | 对实际上传适配器的故障传播、进程停止仍需 M3 联调 |
| 失败文件不得进入上传/交付 | 下载失败不产生成功返回；当前 CLI 完全不提供云端上传或交付；离线测试无云端调用 | 真实 M3/M4 适配器必须验证源收据/重算摘要并接好失败闸门，尚未完成 |

因此可交付的是“源阶段已有证据，后端预算组件及模拟接线通过”。M2 仍保留实际上传期验收项，不以本地模型或旧上传实验替代，也不自行降低完成标准。
