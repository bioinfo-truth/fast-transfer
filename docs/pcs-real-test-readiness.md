## 真实接线前仍需验收的实现

1. **真实响应来源**：独立入口的 Identity/Object/Share provider，精确端点/方法/主机和重定向拒绝，响应限流/大小/时限，严格解析与同一会话 Principal 绑定。不能全局删除默认拒绝门，不能由文件里的 true 产生权限。
2. **预期账号证据**：在允许渠道内先确定独立可信的预期账号引用和命名空间映射，拒绝无证、过期、错配或自我回填。确认官方支持或真实受控验收所需语义后再决定具体 Cookie 请求，不能让适配器自行发现秘密。
3. **对象及分享映射**：精确对象读取范围、相同会话 provenance、shareid→owner/fsid/期限证据来源与严格 decoder；显式承认 path_list 的 TOCTOU。当前 fixture Mapping 不是已经接入的接口。需要历史分享读取时必须单列数据范围，不自动扩张。
4. **生命周期/防重**：短期内存 provider、停止和引用释放、崩溃/日志策略，真实进程重启后的持久单意图和 unknown 核查，以及受批准的私密返回/保留/撤销。现有内存 fixture 账本不能解决重启幂等性；这些实现必须围绕明确的服务与许可范围，不先开 live 再补证。

本轮没有新增可由现有证据唯一确定的 parser 缺口或独立测试目标，因此不增加另一套模型、不重复十五项测试。上述生产语义依赖尚未确认的服务契约/访问范围，不能用 fabricated 响应补齐。准备真实连接仍为 pending，不是“代码测试都过了就能直接登录”。

主机固定为原 dr-who-server 的 fast-transfer 隔离环境；构建须为后来接线完成并再次审查的固定摘要，**不能把当前默认拒绝构建称为可登录构建**。原有工具链/依赖和传输保护不变，无全局 PATH/网络/安全设置修改。

**下一步只有一个优先动作：取得原拒绝控制的范围解释/具体允许依据。** 若仍不可取得，账户动作继续不尝试，状态保持 access_channel_blocked；不请求用户粘贴 Cookie。若依据具备，再确认服务与实现/阶段许可，仍不能跳到一次性泛化“允许登录”。
