# 通用命令的资源采样

通用`task download-next`、`task_upload`及其`--inspect-commit-proof`在结果/受控错误JSON内附加`resource_samples`。它只观察当前任务所在磁盘，以及当前进程/最多64个后代的Linux状态文件；不读取命令行、环境、认证文件或网络统计，不采集同机其他业务进程。

采样默认50毫秒，开始/停止各采一次，内存只保留最小/最大值与计数，不追加无限日志。记录包括耗时、最小采样可用字节、父进程与进程树采样RSS峰值、采样次数/错误、遍历是否截断、线程是否停止和`complete`。正常、受控错误和KeyboardInterrupt都会退出采样上下文。SIGKILL无法输出最终采样汇总，不能将缺失当成零；该场景依靠任务持久状态和外部验收记录。

`complete=true`仅表示采样器正常结束、没有报告读取失败或遍历截断，不证明连续全量测量。采样可能漏掉短暂helper/瞬时峰值；RSS求和可能重复计算共享页。子进程退出窗口可跳过，PID父子关系重新核对以减少误归属；这不提供恶意同UID进程隔离或容器级精确计量。

资源记录**不代替**SpaceGuard磁盘预算、任务超时、SDK单片内存准入和服务端账号限制，也不自行更改`cloud_verified`或`delivered`。采样失败显式`complete=false`，传输状态仍按既有协议与回读校验判断。

结果应由操作者保存到新的私有日志，保留原结果。例如先设置私有umask和shell noclobber，再按操作说明完整填写命令并重定向；不要在未知结果时因为日志缺失就重发上传：

```sh
umask 077
set -C
# 填写完整的已审核task_upload命令参数，输出重定向到新的私有文件
```
