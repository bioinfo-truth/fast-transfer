## 已实现

- 复用 OrderQueue、Task 输入身份、不可变清单及现有 v3 交接校验和交接注册表；R2 阶段单独记账，不伪造旧 Task 的本地源文件状态。
- 专用服务队列统一预约 R2 完整文件大小、暂存数量和执行缓冲，固定一个执行文件，按文件边界轮转订单。旧整文件 worker 不会同时接管此队列。
- multipart 创建前预约，未合并分片、完整对象、等待核验及待清理都占额度；正常对象删除且 HEAD 404 后才释放，进程退出不自动清零。
- 控制机执行锁与 VPS 互斥锁／执行令牌共同保护。旧令牌在云请求前拒绝；无法确认旧执行者停止时不派发新工作。
- 已确认边界可暂停、跨进程复用 R2 对象或 MPU 会话和分片回执。未知写保留记录及额度，不自动重放；有余量时其他订单可继续。
- 已确认执行者停止且没有任何远端写意图的源预检失败，可释放未使用预约并隔离订单。真实不存在源测试中，后一有效订单自动完成。
- 全单文件通过完整回读后才允许整单交接。重复导出复用同一快照和注册记录，云端元数据 MD5 使用既有表示规范化，与内容摘要分别保存。

## 范围与后续

服务默认配置为 256 MiB 缓冲、32 GiB R2 预算、两个暂存对象、最多 64 条订单记录；实网采用更低的 2 MiB 预算测试。每单 50 文件、单文件 15,000,000,000 字节的准入边界有本地验证，尚无对应规模多单实网压测。已完成／失败记录继续计入队列容量，长期归档尚未实现；不能将逻辑账本当作整个 R2 账户物理配额或约束其他独立程序。

本轮实网源适配器限定 NCBI HTTPS，固定单 VPS。多 VPS 迁移、双阶段并行、任意时刻即时取消、源流内逐片暂停、歧义写入自动 abort／回收及长期常驻仍未验收。暂停检查点为源阶段完成或确认边界、百度确认片；未知写须核查，不因测试通过解除这些边界。legacy 测试准入策略未产生分享，不替代正式七天交付配置。

核心模块为 r2_orders、r2_order_runner、r2_live_backend、r2_order_handoff；详细设计、操作入口和脱敏 JSON 分别为 docs/r2-multi-order-plan.md、experiments/r2_multi_order_live.py、docs/validation/r2-multi-order-2026-11-20.json。目前保留在工作区，未推送完整代码或发布生产运行包。现有并行修改保留。后续资源与恢复沿 [Issue #4](https://github.com/bioinfo-truth/fast-transfer/issues/4)，整单交接沿 [Issue #7](https://github.com/bioinfo-truth/fast-transfer/issues/7) 跟踪，不关闭更大范围的生产化任务。

## GB 级测试：合并结果未知的恢复

进行中的双订单测试中，一份约 6.08 GB 文件的全部百度分片已确认，合并请求返回 HTTP 504。只读查询发现目标路径存在同大小文件；随后在境内通过官方接口完整回读，大小、MD5 和 SHA-256 均与源一致，耗时约 537 秒。确认旧执行者停止并核对操作绑定后，使用回读证据确认原合并与校验，未重复上传分片；R2 对象在核验后清理并释放预约。百度元数据所列 MD5 与文件完整内容 MD5 不一致，不能单凭该字段判定文件损坏。

以上为单个真实故障恢复记录，恢复代码仍需更广泛的中断测试；整个六文件 GB 级验收仍在运行。

后续另一订单的一个分片也返回 HTTP 504，结果未知。用户选择允许对两个未知分片各进行一次受控重试：保留原始意图，绑定原会话和内容，记录可能重复传输，其他已确认分片不重传；完成后必须完整回读校验。首个未知分片重试已收到匹配回执，整单验证仍在进行。未知片的首次请求是否生效无法判定，因此不能宣称严格无重复传输。

## 后续调度方向：订单排队、订单内并发（2026-11-21）

### 单文件 1、2、4 片并发对照（2026-11-21）

同一 1.34 GB 公开文件按时间先后比较：1 片约 3.51 MiB/s、2 片约 5.71 MiB/s、4 片约 11.07 MiB/s；四片累计上传 RPC 约 116 秒。四片测试在首批确认后模拟进程中断并恢复，最终完整回读一致，R2 测试暂存清理。四片时 VPS 工作进程采样峰值约 170 MiB；采样可能遗漏短时峰值。两片来自另一轮，同一网络条件并未保证；源暂存曾 SSH 超时，经栅栏确认原 R2 会话无分片后恢复，不能排除重复源读取。

四片为当前测试中最快的候选配置，非已启用的生产默认值。原 256 MiB 地址空间限制下，实验中通过限制内存分配器 arena 才完成四片并发；不同运行环境的安全余量和长时间稳定性仍需验证。工作区的单文件调度已改为优先继续同一就绪订单，暂停或隔离时可转下一个订单，116 项 R2 本地测试通过；该行为尚未实网验证，也没有实现订单内多文件并发。

后续用两个订单、每单两份约 1.38 MB 公开文件实网验证同一服务队列的顺序为 A、A、B、B，四份均完整回读，R2 预约归零。这只验证同一队列、单 VPS 的小文件路径；独立队列之间没有经过跨队列互斥验证，不能据此宣称同一 VPS 所有独立服务共享全局排队。
