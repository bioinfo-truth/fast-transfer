# BaiduPCS-Go 安全认证设计：离线模型

2026-11-09。按用户优先方向验证可实施的安全设计，不接入第三方客户端，不声称登录或分享成功。固定源码诊断及依据见[分享调研](baidu-share-service.md)。未安装/运行 BaiduPCS-Go，未发送百度账户请求，未读取实际 Cookie、BDUSS、STOKEN、OAuth、密码或认证文件，未调整真实 TLS/网络设置。此前站点安全拒绝保持有效，本模型不能用于绕过。

## 模型与边界

`fast_transfer/pcs_auth_simulation.py` 没有 CLI、网络或存储实现，只接受 exact-type FakeTransport 和固定公开假 Cookie。真实值即使格式正确也拒绝。两个 `/offline-design/` 地址是**虚构的模型标签，不是百度 API**。真实接线必须另行选择受支持的账号校验接口并证明身份绑定，不能将本模型字典视作账号认证证据。

状态顺序：输入/范围校验 → 严格 TLS 策略检查 → 模拟可信身份校验 → 与预期账号匹配 → 可选资料查询 → 释放模型凭据引用并关闭 transport。

- SSLContext 来自系统默认可信上下文，必须 CERT_REQUIRED 且 check_hostname=true；关闭任一保护即拒绝。仅接受两个固定 HTTPS 标签，无 HTTP、用户信息、凭据查询参数或跳转。模型完全禁止 HTTP，因而也禁止明文传凭据。该检查不证明真实证书链、SNI、DNS/重定向策略或第三方依赖已修复。
- 身份校验步骤在模型中是独立权威信任边界，只有明确 valid、合法字符串 UID 与预期一致时才建立模拟身份。invalid、格式/身份未知、超时、证书失败、传输失败或账号错配均停止，不查询资料、不重试。
- 资料不作为认证来源。只有身份先建立后，资料超时/不可用才降级；资料账号冲突则拒绝，不静默覆盖身份。force-login 无论名字如何均拒绝，不能用示例身份假装认证。
- Cookie 键数量/顺序、字符、换行和长度先校验，再限制为固定假值；不用于声称覆盖真实 Cookie 的全部合法格式。没有凭据发现、配置、日志或磁盘保存入口，输出只含固定安全状态码，忽略资料自由文本，不传播异常原文。
- finally 清除模型持有的凭据引用并关闭/清空 transport。Python 字符串不能保证内存擦除，调用者或异常 traceback 也可能保留输入；本模型不接受真实秘密，更不宣称实现了安全内存。输出的 reference_released 只表示该局部引用已设空。
- transport 每步最多一次，完成后终止；结果始终 live_authenticated=false、share_eligible=false。没有上传、分享或真实写入能力，也不改变既有工作流资格。

## 接入前仍需解决

模型没有修复发布版的 HTTP 登录依赖、默认跳过证书检查、JSON 持久化或实际身份验证接口。应先审查并实现第三方客户端补丁/受限适配器，逐项验证证书与主机、凭据全路径/依赖、可靠账号身份、无任意 HTTP/跳转、配置权限、异常/日志/崩溃落盘以及终止清理。不能直接把 optional profile 逻辑套到尚未有可信身份的分支。

真实验证前须先有允许的接入渠道，不能通过 CLI 或修改 TLS 绕过既有拒绝。另须针对 fast-transfer 指定测试主机及固定审查构建，明确批准凭据类别和用途、允许请求、账号访问范围、仅内存或隔离持久保存/期限及清理安排；不得混用 Xtransfer token。若需要建链，还须明确指定对象、期限、返回范围及未知结果处理，单独验证路径可达和服务资格。当前不索取或导出凭据、不申请笼统同意、不部署；自动分享仍未完成。
